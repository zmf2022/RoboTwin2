## 3. 数据准备

### 3.1 下载 clean 训练数据（LeRobot 格式）

```bash
hf download TianxingChen/RoboTwin2.0 \
  lerobot_dataset/RoboTwin_lerobot_v30.zip \
  --repo-type dataset --local-dir data

unzip data/lerobot_dataset/RoboTwin_lerobot_v30.zip -d data/training_data/
```

产物 `data/training_data/RoboTwin_lerobot_v30/`：Aloha-Agilex 50 任务 × 50 条 clean，
共 2500 集，LeRobot v3.0 格式

**修复官方 v3.0 缺帧（训练前必做）**：官方 v2.1→v3.0 转换在约 25% 的 episode 中段丢了 1–2 帧（mp4 帧数少于 parquet 行数，与解码后端无关），丢帧处之后画面比 state/action 超前 1 帧，末尾几行读到下一个 episode 的首帧。官方 v2.1 包完好且编码相同，用它无损重建视频（parquet 不变，约 1 分钟，自带逐帧校验）：

```bash
hf download TianxingChen/RoboTwin2.0   lerobot_dataset/RoboTwin_lerobot_v21.zip   --repo-type dataset --local-dir data
mv data/training_data/RoboTwin_lerobot_v30 data/training_data/RoboTwin_lerobot_v30_old
python scripts/fix_v30_videos.py   # RoboTwin_lerobot_v30_old -> RoboTwin_lerobot_v30
```

修复后的数据沿用原名 `RoboTwin_lerobot_v30`，原始数据留在 `RoboTwin_lerobot_v30_old`；换机器可直接拷贝修复后的目录（2.3G）。


### 3.2 randomized 数据转 LeRobot（仅供评测/泛化对比，禁止参与训练）

仿真评测（§5.2 `--task_config demo_randomized`）不需要数据；
只有拿 random 轨迹做训练对比时才需要转。转换脚本已移植在 `scripts/convert/`

产物：`$HF_LEROBOT_HOME/demo_randomized/`（默认 `~/.cache/huggingface/lerobot/`）。

## 4. 模型训练

### 4.1 全参微调（多卡，效果最好）

单卡 72GB 放不下 6.4B 全参训练，需多卡：

| 卡数 | MBS | 备注 |
|---|---|---|
| 2 | 1～2 | 需加 `--train.enable_full_shard true` |
| 4 | 4 | 最低推荐 |
| 8 | 8～16 | 推荐 |

```bash
cd lingbot-vla-v2
conda activate robotwin
NGPU=$(nvidia-smi -L | wc -l)
MBS=8
bash ../scripts/train.sh ../scripts/robotwin_local.yaml \
  --train.micro_batch_size $MBS \
  --train.gradient_accumulation_steps $((1024 / (MBS * NGPU))) \
  --train.global_batch_size 1024 \
  --train.enable_gradient_checkpointing true \
  --data.num_workers 4 \
  --data.prefetch_factor 1
```

- global batch 固定 1024（= MBS × NGPU × 累积），OOM 就把 MBS 减半。
- `num_workers` / `prefetch_factor` 必须调小，默认值（20/4）会撑爆主机内存。
- 日志：`lingbot-vla-v2/log.txt`；checkpoint：`lingbot-vla-v2/output/checkpoints/global_step_<N>/hf_ckpt/`。

### 4.2 非全参微调（单卡）

冻结 Qwen3-VL（4.44B），只训 action expert + 对齐头（1.93B）。

```bash
cd lingbot-vla-v2
conda activate robotwin
MBS=4   # OOM 改 2
bash ../scripts/train.sh ../scripts/robotwin_local.yaml \
  --train.train_expert_only true \
  --train.output_dir output_expert/ \
  --train.max_steps 12000 \
  --train.save_steps 6000 \
  --train.micro_batch_size $MBS \
  --train.gradient_accumulation_steps $((1024 / MBS)) \
  --train.global_batch_size 1024 \
  --train.enable_gradient_checkpointing true \
  --data.num_workers 4 \
  --data.prefetch_factor 1
```

保效果要点：
- 单卡 50k 步需约 68 天，改为 12000 步（约 22 epoch、16 天），余弦 lr 在 12000 步内退火完；batch 1024、lr 1e-4、FP32 不变。
- 两个 checkpoint 都评测，按 clean + randomized 均值选（冻结 VLM 后 randomized 泛化通常更稳，clean 可能偏低）。
- 评测：`bash scripts/eval.sh lingbot-vla-v2/output_expert/checkpoints/global_step_<N>/hf_ckpt 1 6`。

### 4.3 LoRA 微调（单卡，非全参里效果最好）

action expert（1.79B）+ 对齐头全参训练；VLM 的 LLM 部分（q/k/v/o/gate/up/down，36 层）挂 LoRA（r=32、alpha=64，66.1M 参数），视觉塔、embedding、LayerNorm 冻结。与 4.2 相比 VLM 能适配仿真画面，深度/视频蒸馏也能反传到 VLM。

实测（batch 32 每步耗时，单卡）：基线 MBS 4 + 梯度检查点 5.04s；关检查点 4.36s；MBS 8 4.43s；多加 dataloader 进程无效（GPU 利用率已 95%）；**MBS 8 + 关检查点 + expandable_segments 4.03s（快 20%，峰值显存 69.8G）**，以上均不改 batch/超参，效果等价。

```bash
cd lingbot-vla-v2
conda activate robotwin
MBS=8   # OOM 退回 MBS=4
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True setsid nohup \
bash ../scripts/train.sh ../scripts/robotwin_local.yaml \
  --train.lora_rank 32 \
  --train.lora_alpha 64 \
  --data.random_aug_config ../scripts/random_aug/random_aug_onepass.yaml \
  --train.output_dir output_lora_aug/ \
  --train.max_steps 20000 \
  --train.save_steps 5000 \
  --train.save_total_limit 3 \
  --train.micro_batch_size $MBS \
  --train.gradient_accumulation_steps $((256 / MBS)) \
  --train.global_batch_size 256 \
  --train.enable_gradient_checkpointing false \
  --data.image_augment true \
  --data.num_workers 4 \
  --data.prefetch_factor 1 > train_lora_aug_$(date +%m%d_%H%M).log 2>&1 < /dev/null &
tail -f log.txt
pkill -f train_lingbotvla.py   # 停止；不删输出目录、用相同参数重跑即断点续训
```

- 本机约 27 s/步（1 epoch ≈ 2144 步），20000 步约 6.3 天；cosine 只从 1e-4 降到 5e-5，中间的 checkpoint 与提前结束的训练基本等价（本机训练时 GPU 被占满，中间 checkpoint 拷到 A100 上评）。
- 每个 checkpoint 约 57G（`hf_ckpt` 24G + 续训用的 DCP 33G）。`--train.save_total_limit 3`：每次存完只留最新 3 个 `global_step_*`，删最早的（插值等其他目录不动；存新的时短暂有 4 个，需约 230G 空间）。被删的 checkpoint 不能再评测，要留就先拷走它的 `hf_ckpt`。
- `--data.random_aug_config` 是 clean 随机化增强（见 4.4）；去掉即纯 clean LoRA。
- `image_augment`：训练时亮度 0.7～1.3、对比度 0.6～1.4、饱和度 0.5～1.5 抖动（同一样本各视角一致），对应 randomized 的光照变化，耗时 +3%。
- LoRA 参数走 AdamW，其余可训参数仍用 Muon；保存 `hf_ckpt` 时自动把 LoRA 合并回原权重（已验证：无 LoRA 键、键名与基座一致、冻结部分不变），评测命令不变：`bash scripts/eval.sh lingbot-vla-v2/output_lora_aug/checkpoints/global_step_<N>/hf_ckpt 1 6`。
- 未调优项：r 32/64、LoRA lr。
- 实现：`lingbotvla/utils/vla_lora.py`，`--train.lora_rank 0`（默认）即关闭。

## 5. 模型评估

直接在本仓库评测（`scripts/eval.sh` + `scripts/eval_lingbotvla_client.py`，协议同 RoboTwin 官方：种子 100000 起、专家校验、每任务 100 次、clean 用 seen 指令、randomized 用 unseen 指令、FP32）。同一次 `eval.sh` 里任务崩溃会自动重试（最多 3 次），从该任务的 `progress.jsonl` 接着跑；重新执行 `eval.sh` 会新建结果目录、从头评测。
一条命令跑完 50 任务 × clean + randomized × 100 次：

```bash
conda activate robotwin
bash scripts/eval.sh <模型目录> [num_gpus] [clients_per_gpu]   # 每卡 1 个推理 server，多个仿真 client 共用（每 client 约 1 核 CPU、5–7G 显存；72G 卡最多 6 个；A100 80G 的 clean 可 8 个，randomized 最多 6 个，8 个会爆显存）
```

### 5.1 官方 RoboTwin 后训练权重（基准对照）

官方在 clean+randomized 上后训练的对照模型（README 报告 clean 93.52% / randomized 92.80%，**用了 randomized 数据，不可比、禁止作为提交起点**），仅用于评测链路对拍与差距分析：

```bash
bash scripts/eval.sh /mnt/datadisk/models/lingbot-vla/lingbot-vla-v2-6b-robotwin/checkpoints/global_step_50000/hf_ckpt 1 6
```

本机快速子集（10 任务 × 20 个种子，任务列表见 `赛题要求与冲榜方案.md` §七）实测 clean 92.5% / randomized 91.5%，与 README 一致，评测链路无误。

## 7. 常见坑

| 现象 | 解法 |
|---|---|
| 推理找不到 Qwen 权重 | 检查 `QWEN3VL_PATH` 是否指向 `Qwen3-VL-4B-Instruct` 目录 |
| `eval.sh` 报 `no config.json` | 参数必须指到 `checkpoints/global_step_<N>/hf_ckpt/`，不是父目录 |
| 训练进程无报错直接消失（日志停在第一个 batch） | 主机内存 OOM：加 `--data.num_workers 4 --data.prefetch_factor 1` |
| 训练 `CUDA out of memory` | 减小 `MBS` 并相应增大梯度累积；单卡 72GB 无法全参训练，需 ≥2 卡 |
| 评测显存不够 | 每卡 1 个 server 约 26GB + 每个 client 约 5–7GB（randomized 更高），减小 `clients_per_gpu`；训练与评测不能同卡同时跑 |
| 下载慢 / 断 | `HF_ENDPOINT=https://hf-mirror.com` + `hf_transfer` |
| 成绩与官方对不上 | 确认 FP32 + `demo_clean` + `use_length` 默认 50 未改 |
