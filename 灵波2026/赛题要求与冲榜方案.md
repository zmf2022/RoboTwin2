## 二、对标与差距

### 1. 官方排行榜 = 本赛协议

[RoboTwin 2.0 Leaderboard](https://robotwin-platform.github.io/leaderboard) 的设定与本赛完全一致：50 任务 × 50 条 demo_clean 训练，clean / randomized 各 100 次评测。榜单即对标（2026-09-01 快照）：

| 方法 | clean | randomized | 平均 | 备注 |
|---|---|---|---|---|
| OLA-Sem | 75.1% | 67.6% | 71.3% | 平均第 1 |
| GigaBrain-0.7 | 66.8% | **67.9%** | 67.3% | randomized 第 1，且高于 clean |
| 4D-WAM | 81.5% | 41.8% | 61.6% | |
| π0.5 | 70.7% | 46.0% | 58.4% | |
| OLA-Geo | **83.0%** | 33.6% | 58.3% | clean 高、random 崩 |
| FastWAM | 77.8% | **1.9%** | 39.9% | 典型过拟合干净场景 |

官方 LingBot-VLA 2.0 README 的 93.52% / 92.80% 用了 randomized 数据训练，**不可比**。

### 2. 结论

1. **目标线**：clean ≥ 85%、randomized ≥ 70%，即超过榜单全部方法。
2. **clean 80% 不难，决胜在 randomized**。多个方法 clean 很高但 random 崩溃，说明微调把"干净场景"背下来了、破坏了预训练的通用视觉表征。
3. **榜首的共性是强预训练表征且被保住**。LingBot-VLA 2.0 有约 6 万小时预训练，底子好。核心思路：**别在微调中把预训练练坏 + 用增强把 clean 数据变多样**。
4. 逐任务看：`lift_pot`、`handover_mic`、`beat_block_hammer` 等 clean 近 100% 但 random 大跌，是纯视觉鲁棒性问题，**提分空间最大**；`hanging_mug`、`blocks_ranking_size`、`move_stapler_pad`、`handover_block` 所有方法都低，投入产出比低，放最后。

### 3. 算力现状

本机只有 1 张 72GB 卡，全参训练放不下（见实战文档 §4），**训练上 AMD 云多卡**，本机只做评测（FP32 推理 + 仿真约 32GB/路）。

## 三、合规要点（先做，避免白干）

1. **起点只能用基座** `robbyant/lingbot-vla-v2-6b`。**禁止**用 `lingbot-vla-v2-6b-robotwin`（官方 RoboTwin 后训练权重，训练时用了 randomized 数据）。
2. **重算归一化统计**：官方 `assets/norm_stats/robotwin.json` 是在 clean+randomized 上统计的，属于 randomized 数据参与训练的灰色地带。用 clean 数据重算一份，配置里 `--data.norm_stats_file` 指向新文件。
3. **不要自己用 RoboTwin 采新数据**（即使是 clean）："统一使用 … 每个任务 50 条"意味着数据量固定。需要的话先在钉钉群问清楚。
4. 以下做法按"改进数据处理方式"理解应属允许，但**建议群里确认**后再上：离线图像增强/背景替换、用大模型改写训练指令、用 RoboTwin 自带纹理素材做增强。
5. `04_复现与调优说明` 里如实写清所有数据处理，保证主办方能一键复现。

## 四、冲榜方案

标 ⚠️ 的做法可能碰到规则边界，先在钉钉群确认。所有提升幅度都需在快速评测子集上 A/B 验证。

### A. 保住预训练表征（randomized 核心）

1. **权重插值（WiSE-FT / RETAIN）**：`θ = α·θ_微调 + (1-α)·θ_基座`，扫 α ∈ {0.5, 0.6, …, 1.0}。RETAIN 专门在 VLA 上验证了对分布外有显著提升。**零训练成本，本机可做，性价比第一。**
2. **少训、早停**：每 2.5k 步存 checkpoint，画 step–成功率曲线，按 (clean + random)/2 选点。clean 数据约 55 万帧，官方 50000 步 × 1024 ≈ 93 个 epoch，大概率过拟合。
3. **少改动预训练部分**：`freeze_vision_encoder: true`，或 VLM 部分学习率降 10 倍，主要训练动作专家。
4. **保留并可加大 DINO / 深度蒸馏损失**：它们把视觉特征对齐到对背景、光照鲁棒的表征（`depth_loss_weight`、`future_video_loss_weight`）。LingBot-VLA 1.0 论文报告深度在 randomized 上收益（约 +8.6 点）大于 clean（约 +3.8 点）。
5. **权重平均（model soup）**：多个 checkpoint 或多次训练取平均，零推理成本。

### B. 用 clean 数据造出"随机化"（数据侧）

| 扰动 | 做法 | 参考 |
|---|---|---|
| 随机背景/桌面纹理 | 头部相机固定：对大量帧取中位数得到"空场景图"，差异大的像素为前景（机械臂+物体），其余是背景掩码；背景贴随机纹理。腕部相机按桌面颜色阈值分割 | GreenAug、RoboEngine |
| 桌面杂物 | 用前景掩码从其他任务抠物体，贴到桌面空白处（避开目标物与机械臂） | ROSIE 思路，不用生成模型 |
| 综合外观变化 | 视频生成模型改背景/材质/颜色，动作标签不变（成本高） | ReShoot：LIBERO-Plus +3.2 点，相机视角变化 +22.5 点 |
| 随机光照 | 官方 `--data.image_augment true`（亮度/对比度/饱和度，跨视角一致）；再加色温、gamma、局部高光、极端亮暗 | — |
| 桌面高度 ±3cm | 头部相机小幅随机缩放/平移 | — |

原则：同一样本多视角、多帧用同一组增强参数（与官方实现一致）；增强强度以 clean 分不明显下降为限。

⚠️ RoboTwin 自带背景纹理库正是 randomized 场景用的素材，用它做增强效果可能最好，但离"使用 randomized 数据"最近，**必须先确认**。公开纹理数据集（如 DTD）更安全。

⚠️ **红线**：在仿真里重放 clean 轨迹并打开随机化重新渲染，等于生成 randomized 数据，大概率违规。

### C. 语言泛化（randomized 用 unseen 指令）

1. **离线改写训练指令**：大模型为每条指令生成多种同义说法（保留物体、颜色、左右手），训练时随机抽。训练集约每条轨迹一条指令（`meta/tasks.parquet` 共 2411 条）。
2. **指令写短**：CVPR 2025 RoboTwin 挑战赛报告发现简洁的高层指令比细节多的指令泛化更好，可试把训练指令统一成精简格式。
   ⚠️ 推理时用大模型把 unseen 指令改写成该格式，属推理策略，需确认合规。

### D. 训练配方（主要提 clean）

1. **按任务均衡采样**：单条轨迹 74～894 帧，按帧采样时长任务占比过大；改为按任务均衡，再对弱任务加权（数据量不变）。
2. **末端位姿辅助监督**：挑战赛冠军 AnchorDP3 同时监督关节角和末端位姿。现有数据只有关节角，可用正运动学算出末端位姿，配置里已预留 `end.position`。
3. **状态输入 dropout**：训练时随机遮掉部分关节状态，防止模型只抄上一步状态而不看图像。
4. 学习率 / `lr_min` / warmup，Muon vs AdamW 对比。
5. 关键位姿思路（AnchorDP3，98.7%）：只预测抓取前、抓取、放置等关键位姿。效果好但要改结构、依赖场景真值，仅作参考。

### E. 推理策略（不用重训，本机即可扫）

1. **`--use_length`**：动作块执行长度，默认 50 步开环。扫 10 / 25 / 50，越短越能根据画面纠偏。
2. **BID 多候选择优**：一次采样多个动作块，选与上一段轨迹最连贯的，适合 flow matching，无需训练。
3. **RTC 平滑衔接**：新动作块生成时固定已执行部分，只补全其余，保证衔接平滑。
4. **动作平滑（ensemble）**：`deploy/lingbot_vla_v2_policy.py` 已有 `adaptive_ensemble_alpha`、`action_ensemble_horizon`，接到评测脚本上试。
5. 去噪步数 `num_steps`（默认 10）扫 5 / 10 / 20；夹爪维度加迟滞阈值防止来回开合。
6. **必须 FP32 推理**（BF16 成功率对不上）。

### F. 按任务分析

- 全量结果出来后按任务排序，区分"clean 就差"（能力问题 → 训练配方、采样加权）和"只有 random 差"（泛化问题 → 增强）。
- 优先攻 clean 高、random 崩的任务；看 `eval_results/` 失败视频找系统性失败模式。

### 推荐顺序

| 阶段 | 内容 | 预期 |
|---|---|---|
| 1 | 基线训练，密集存 checkpoint，画步数曲线 | 拿到起点 |
| 2 | **权重插值扫 α** + 推理参数扫描（执行长度、BID、平滑） | 不用重训，random 提升最快 |
| 3 | `image_augment`、按任务均衡采样、冻结/降低视觉部分学习率 | 改配置即可 |
| 4 | **背景替换 + 贴干扰物 + 指令改写** | random 主要提分项，开发量最大，要尽早启动 |
| 5 | 权重平均、逐任务失败分析 | 冲刺 |

## 五、决赛准备（决定第一名）

决赛是 3 天真机：Day1 调试环境，Day2–3 采数 + 微调 + 真机推理 + 评测，赛题当天公布。平台大概率是松灵 Cobot Magic（赞助商）。

提前演练的能力：
1. **真机微调全流程脚本化**：采数 → 转 LeRobot → 算 norm stats → 训练（`configs/vla/real_robot/real_robot.yaml`）→ 导出 `hf_ckpt` → 部署推理，一条命令串起来。
2. **少样本快速适配**：演练"几十条示教、几小时训练"能出可用策略的配方（步数、学习率、冻结策略、batch），官方只写了提供"边缘推理算力"，现场训练算力未说明，需向主办方确认或自备（可提前在云上准备好训练环境）。
3. 真机推理稳定性：动作块长度、ensemble、控制频率、夹爪阈值等部署细节。
4. 初赛做一个**真机创新 Demo**（可选任务），既加晋级筛选分，又是决赛的彩排。
